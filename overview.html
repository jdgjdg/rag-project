RAG System

Database Course Assistant

A Retrieval-Augmented Generation chatbot that helps students learn database concepts from lecture material — without giving away assignment answers.

Overview

What the system does

📚 Retrieves course material

When a student asks a question, the system searches a vector database of chunked lecture slides and cleaned transcripts to find the most relevant passages.

🤖 Generates Socratic answers

A Gemini LLM reads those passages and produces a concise, step-by-step response — asking guiding questions rather than handing over solutions.

🛡️ Blocks assignment leakage

A separate vector index of assignment questions detects verbatim or near-verbatim matches. On a hit, the assistant asks the student what they've already tried instead of providing any guidance.

🔄 Handles quota limits

If a Gemini model hits its rate limit (HTTP 429), the system automatically falls back through a chain of four models, so the service stays up.

Architecture

Request flow — what happens when a student asks a question

Browser (Angular :4200) → POST /query with { question, history[] }
FastAPI server (api.py :8000) Receives request, orchestrates the pipeline
├─ assignment_guard.py Cosine similarity search against chroma_assignment/. If score ≥ 0.80 → sets is_assignment = True
└─ chain.py Builds the RAG chain, invokes LLM, handles fallback
├─ retriever.py — fetch Searches chroma_db/ with Gemini embeddings → top 6 chunks

Components

Component deep-dives

config.py — Central configuration

Single source of truth for every tunable constant. Change things here and they propagate everywhere.

ConstantDefaultEffect
CHUNK_SIZE1000 charsHow much text each vector represents
CHUNK_OVERLAP200 charsContext continuity across chunk boundaries
TOP_K6Chunks retrieved from Chroma per query
RERANK_TOP_N3Chunks passed to the LLM after reranking
SIMILARITY_THRESHOLD0.80Cosine similarity cutoff for assignment detection
FALLBACK_MODELS4 modelsTried in order when the previous one hits 429

ingest.py — Document ingestion pipeline

Run this once before starting the API. It reads data_clean/, splits every document into overlapping chunks, embeds them with Gemini embedding-001, and writes the results to chroma_db/. Batches 10 chunks at a time (30 s delay between batches) to respect API quotas. Progress is saved to embed_progress.json after every batch, so an interrupted run can resume exactly where it left off.

python ingest.py

retriever.py — Retrieval & reranking

Two-stage retrieval improves answer quality significantly over raw similarity search:

  1. Bi-encoder (Chroma + Gemini) — fast ANN search, optimised for recall → returns top 6 chunks.
  2. Cross-encoder (ms-marco-MiniLM-L-6-v2) — scores every (query, chunk) pair precisely, optimised for precision → keeps top 3.

The multi-query retriever variant (used when the first answer contains the fail-safe phrase) generates 3 alternative phrasings of the question with an LLM, retrieves chunks for each, deduplicates, then reranks the union. This overcomes cases where the student's wording doesn't match the lecture's wording.

assignment_guard.py — Academic integrity guard

On first API startup (or if chroma_assignment/ doesn't exist) the file data_clean/assignment_questions_clean.txt is embedded and stored as a second Chroma collection.

Every incoming question is compared against this index. Chroma returns a cosine distance; the code converts it to a similarity score (1 − distance). If the score is ≥ 0.80, the question is flagged and the system prompt is overridden with an instruction to ask the student what they've already tried — no hints, no partial answers.

chain.py — RAG chain & model fallback

Builds a LangChain LCEL chain: retriever → reranker → prompt → LLM → string output. The system prompt instructs the model to act as a Socratic database tutor and to say "I lack specific course context" if the retrieved chunks aren't relevant enough. invoke_with_fallback() catches that phrase and retries with multi-query retrieval before escalating.

On HTTP 429 (quota exceeded), the current model is marked exhausted and the next model in FALLBACK_MODELS is tried. Exhausted models are remembered for the lifetime of the server process.

api.py — FastAPI server

Single endpoint: POST /query. On startup (via lifespan), it loads both Chroma collections and creates both retriever variants — so they're warm for every request. CORS is restricted to localhost:4200.

Sources returned to the frontend are the unique filenames from chunks retrieved by the simple retriever, giving students visibility into which lectures were consulted.

frontend/chat/ — Angular 19 UI

Standalone Angular component (no NgModule). All state is in-memory — switching or refreshing clears chats. The full conversation history is serialised and sent with every request so the backend can be completely stateless. Session limit of 10 questions is enforced client-side via a dot-progress indicator.

Markdown rendering via marked lets the LLM use formatting. PrimeNG provides the spinner, tags, and buttons.

1

Install Python dependencies

python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
2

Add your Google API key

Create .env in the project root:

GOOGLE_API_KEY=your_key_here
3

Build the vector database (first run only)

python ingest.py

4

Install frontend dependencies (first run only)

cd frontend/chat
npm install
5

Launch

start.bat          # Windows one-click
# or manually:
uvicorn api:app --reload        # terminal 1 (port 8000)
cd frontend/chat && npm start   # terminal 2 (port 4200)
Resilience

Model fallback chain

Each Gemini model has its own free-tier quota. When a model returns HTTP 429 it is marked exhausted for the process lifetime and the next model is tried immediately.

#ModelRole
1 gemini-3-flash-preview Primary — good balance of speed and quality
2 gemini-2.5-flash Reliable stable fallback
3 gemini-3.1-flash-lite-preview Most generous quota
4 gemini-2.5-flash-lite Last resort

The model actually used is returned in the API response and displayed under every assistant message in the UI.

Prompt engineering

System prompt design

Role & source restriction

The LLM is told it is a "Supportive Database Tutor" whose only permitted sources are the provided lecture context and official PostgreSQL / PyMongo / Neo4j docs. If the context is insufficient it must say the sentinel phrase "I lack specific course context" rather than hallucinating.

Guardrails

Explicitly forbidden: full ERDs, schemas, code solutions, or BCNF/3NF derivations. User input is wrapped in <user_query> XML tags and the prompt instructs the model to treat the tag contents as data only, ignoring any override instructions.

Socratic protocol

Responses must: identify the core concept, ask one targeted question, validate small wins before moving on, and offer a real-world analogy after 3+ failed attempts. Responses are capped at 150 words where possible.

Assignment override

When assignment_guard flags a question, an additional CRITICAL OVERRIDE block is appended to the system prompt. It forbids any guidance and instructs the model to acknowledge the assignment question and ask what the student has tried.
