### Introduction to MongoDB
We are going to look at MongoDB, a commonly used NoSQL database, and compare it to relational databases. We will use a Jupyter notebook for this demonstration. Our first step is to connect to the database running on this computer using a library called `pyMongo`. We must import this library to connect to the MongoDB server.

An important note that will affect our examples is the programming language we are using. Jupyter Notebook is built on top of Python, so we are running Python code and making MongoDB library calls from Python. MongoDB does not have a separate programming language analogous to SQL; it is built using these library calls. This differs from using the MongoDB client itself, which is based on JavaScript. Consequently, the library calls are slightly different for each language to ensure they are idiomatic.

### MongoDB Concepts vs. Relational Concepts
To start, let’s compare MongoDB concepts to their roughly equivalent relational concepts:

*   **Databases:** These are called databases in both systems.
*   **Collections and Documents:** Instead of a table, MongoDB uses a collection of documents. A document corresponds to an individual row, and a collection is a group of those documents.
*   **Fields:** In a document, we have key-value pairs called fields, which are equivalent to attributes in relational databases.
*   **Primary Keys:** Each document has its own primary key, just like a relational table. In MongoDB, this field is always named `_id`.
*   **Embedding:** A value of a key-value pair can itself be a document. This is known as an embedded document. Embedding is a critical concept because it corresponds to joining tables in a relational database.

To perform basic queries, we use the `find_one` method on the collection. Providing no conditions returns an arbitrary document. You will see that even though we did not enter a value for `_id`, it exists and contains an `ObjectId`, which is a unique identifier that we will describe later.

Using `collection.find()` returns a cursor object rather than the data itself. Since we are using Python, we convert that cursor object into a list. This produces a Python list containing all of our documents. Because we provided no conditions, it returns every document, each containing an `ObjectId`.
