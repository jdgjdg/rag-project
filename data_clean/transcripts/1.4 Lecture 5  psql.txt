In this course, we have been using Jupyter Notebook as our client to the Postgres database server. This means that we type commands into our client, Jupyter Notebook, which sends information to the server. The server runs the query or performs other operations and produces results, which are then sent back to our client for display.

This approach has a couple of limitations. First, Jupyter Notebook is a rather limited IDE for writing large sections of code. For extensive coding, a dedicated editor is preferable. Second, we will be introducing another client called PSQL, which has special permissions to execute specific commands on the database server. We will focus on some of these special commands that are not available when using Jupyter Notebook.

To start PSQL, instructions will be provided separately as they vary by operating system and platform. Here, we will focus on logging into PSQL once it has been started. I will start it on this Windows machine. Typically, you will be using it in Vocareum. For this demonstration, I am using localhost, meaning this machine. I will be using the `ricedb` database on the standard port, logging in as `riceuser` with the correct password. These parameters mimic what is usually entered in Jupyter Notebook on one of the first lines when logging in.

This is our prompt within PSQL. I want to demonstrate some commands. The first one is `\i` or `\include`. All special PSQL commands begin with a backslash. `\i` or `\include` loads SQL code from a file. In this case, I will use `C:\users\rice\o\desktop\sample_include.sql`. You can see that it indicates a table has been dropped, a table has been created, and a couple of pieces of data have been inserted. We will get to using that data.

One more comment on `\include`: a peculiar aspect of PSQL, even in the Windows version, is that you must use forward slashes in the path, not backward slashes as is standard in Windows. On macOS or Linux, forward slashes are the standard in paths anyway.

At the prompt, you can also run any SQL query or command. For example, I can select everything from the table that was just defined. It contains some data, but it is not a very large table. Let's load some more data. `\i` is for loading SQL. There is another command, `\copy`, for loading data. It can be used for both loading data into the database and writing it out to a file, depending on the operands. I will use `\copy sample from` followed by the path `users\rice\desktop\sample_copy.csv`. I need to specify that this is a CSV file with headers. It has copied four pieces of data into the table. We can examine the data again to see the additional entries.

A few other important commands to illustrate are `\d` for Describe. This lists all the tables defined. Another command is `\?` for help on all PSQL commands. There are many commands, which you can explore at your leisure. One point to note is that there are numerous options for the `\d` command. As we learn about creating other types of objects besides tables, we can get lists of what is defined in our database. Again, all these backslash commands are only accessible within PSQL because PSQL has special permissions for certain operations.

Finally, another useful command is `\q` for quit.

In summary, I have demonstrated some basic features of PSQL, another client for our database. While we will primarily use Jupyter Notebook for most tasks, PSQL is more suitable for writing large SQL programs in a dedicated editor designed for extensive code entry. PSQL then serves as a good tool for loading that code into the database.
