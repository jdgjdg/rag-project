## First Query: SELECT, FROM, WHERE

Our first query is defined via relational calculus: we want all product names for products P where the product price is greater than 15. What is the equivalent SQL syntax? Let's type that in.

We will use SELECT, FROM, and WHERE clauses. FROM specifies where we are getting the data; in this case, from the product table. We will rename it simply as 'p', as in the relational calculus query. The condition is that the product price (prod_price) should be greater than 15. The desired result is all of the product names (prod_names).

Let's see what happens.

## Handling Type Mismatch Errors

We have an error. Interpreting such error messages is a skill you will need to develop. I will help you with that.

The error message states: 'operator does not exist: money > integer'. prod_price was defined as an attribute of type 'money'. 15 is clearly an integer, and the 'greater than' operator cannot compare 'money' and 'integer' types.

To fix this, I will cast 15 to 'money'. This syntax casts the integer to 'money'. This fixes the problem, performs the comparison, and provides the results.

## Retrieving Multiple Attributes

Consider an example to retrieve all product names and prices. I will SELECT prod_name and prod_price FROM product AS P. In this case, I want all products, so a WHERE clause is not needed. This retrieves all data, but only for the two specified attributes.

## Retrieving All Attributes with `SELECT *`

For the next example, to retrieve all attributes for all products (the entire table), I could list all table attributes. Instead, I will use the shorthand '*' which retrieves the entire table.

Using '*' is generally considered bad practice. You should typically list all the attributes you want, in the desired order. Attributes can change, so it's best to be specific about what you need. I am using '*' here partly to demonstrate its existence. I will also use it in various examples to speed up typing or to save space on slides.

## Filtering by Multiple Manufacturers

To find all products made by two specific manufacturers, I will SELECT * FROM product AS p. There are a couple of ways to write this condition.

The first way is: `WHERE p.prod_manufacturer = 'GizmoWorks' OR p.prod_manufacturer = ''`. Always use single quotes, not double quotes. This retrieves the desired products.

### Common Error: Incorrect Boolean Logic

For another version, consider what happens if we write the condition like this (a common student mistake): `p.prod_manufacturer = 'GizmoWorks' OR 'WidgetsAreUs'`. While natural in English, this will result in an error. The error message will appear.

The relevant error message is: 'invalid input syntax for type boolean: "WidgetsAreUs"'. This means 'WidgetsAreUs' is not a Boolean value. The issue is that we are attempting to combine a Boolean result from a comparison with a string using 'OR'. A string is not a Boolean.

### Using the `IN` Operator

We need to write it as before, with a comparison on each side of the OR. The intuition for this example is to find products where the manufacturer is one of several specified values. A different way to express this is using the `IN` operator: `prod_manufacturer IN ('GizmoWorks', 'WidgetsAreUs')`. This yields the same result.

## Filtering by Price Range

Let's find all products within the price range of 20 to 40. We will explore a couple of different versions for this.

`SELECT * FROM product AS P WHERE p.prod_price >= 20 AND p.prod_price <= 40`.

As seen previously, I need to cast 20 and 40 to 'money' type. This retrieves the values. For example, a prod_price of 30 is clearly in that range.

### Using the `BETWEEN...AND` Operator

The second way is to use the `BETWEEN` operator. The syntax is `prod_price BETWEEN 20 AND 40`. This yields the same result. The `BETWEEN...AND` construct is a combined keyword that allows you to specify a range.

## Handling NULL Values with `IS NOT NULL`

To find all products with a defined price, meaning the price is not NULL. The syntax for this is: `SELECT * FROM product AS p WHERE p.prod_price IS NOT NULL`. This checks for a specific condition, not just a value greater than zero; it specifically checks for non-NULL values. This returns the four products that have a value for `prod_price`.

## Pattern Matching with `LIKE`

To find all products named 'widget', which is similar to a previous example. We could simply ask for equality: `p.prod_name = 'Widget'`. Another, very similar, way uses the `LIKE` keyword. I will explain this syntax shortly.

This performs pattern matching. It declares a pattern that will be compared to all product names. Specifically, this pattern (`%Widget%`) means I want the word 'Widget' to be present anywhere within the string, allowing any characters before (`%`) and after (`%`) it. Running this query returns not only 'Widget' but also 'HyperWidget', as 'HYPER' appears before 'Widget'.
