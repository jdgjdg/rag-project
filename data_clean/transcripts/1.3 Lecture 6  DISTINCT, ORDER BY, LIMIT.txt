# Picking a Subset of Results

As a last set of examples, I want to look at the problem of trying to pick a subset of our results. There are several reasons why we might want to do this. Maybe the results that we have are just too big, and we only want to see a sampling of them. Or maybe we only want to see the "best" results in some sense.

Specifically, I'm going to break this down into three categories:
1.  An arbitrary subset: whatever set the system picks for us.
2.  A top subset: the "best" ones in some sense.
3.  A truly random subset: where each time we run it, we get a different random subset, and it's statistically randomized.

We're only going to look at the first two of these. The third of these we'll look at later in the course.

## Arbitrary Subsets with `LIMIT`

For an arbitrary subset, we can simply use the `LIMIT` keyword. If I want two results, I can simply say `LIMIT 2`, and it will show me two results, two tuples of data of whatever shape I requested.

## Top Subsets with `ORDER BY` and `LIMIT`

If I want the top or the "best" subset, I need to specify what I mean by "being the best." In other words, I need to specify how we're going to order the data. So, we're going to use `ORDER BY` to sort the data and then `LIMIT` to pick the top values, as in this example here.

I'm sorting by the `prod_price`, which by default means in ascending order. Then I pick the top two, which means the cheapest two in this case. Executing that, we see that we get the two products that are each $10.

## SQL `LIMIT` Keyword Variations

A little side note: this is PostgreSQL, and some other variants of SQL use other ways for doing the `LIMIT`. Some of them use a `TOP` keyword, and some of them also use something known as `KEYNUM` to pick things. I'm not going to go into those details; look those up if you are working with different versions of SQL.
